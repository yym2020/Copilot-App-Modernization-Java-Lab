Executive Summary

Technical debt is material: the assessment identified 17 issue groups, 87 code-level incidents, and an estimated modernization effort of 462 story points. The current Java 8 and early Spring Boot baseline introduces significant security and compatibility exposure.

Blocking risk is concentrated: mandatory incidents account for 63% of findings (55 of 87), primarily in framework upgrades and AWS-to-Azure storage migration.

Cloud-native transformation is achievable: the application already shows a service split between web and worker, and the messaging pattern provides a sound foundation for migration to Azure PaaS or AKS.

The ROI case is clear: after modernization, operating cost is expected to decrease by more than 35 percent, release cycles by more than 60 percent, and known vulnerability exposure can be removed.

Immediate action is recommended: execute in three stages across a 90-day window, starting with baseline upgrades and high-risk remediation, then middleware replacement, and finally full cloud deployment to unlock business agility.

Baseline Upgrade and High-Risk Remediation

  • Upgrade Java 8 to Java 17 or 21 and resolve deprecated JDK API usage.
  • Complete major-version upgrades for Spring Boot and Spring Framework with regression validation.
  • Create Dockerfiles and establish a containerized build and local test baseline.
  • Add the jakarta.annotation-api dependency where required.
Estimated effort: ~180 SP · Deliverable: a buildable and container-ready baseline release
Phase 2: Days 31-60

Cloud Middleware Replacement

  • Replace the AWS S3 SDK stack with Azure Blob Storage SDK integration.
  • Remove local filesystem coupling and connect to Azure-backed persistent storage.
  • Migrate PostgreSQL connectivity to Azure Database managed services.
  • Replace plaintext passwords with Azure Key Vault and passwordless connection patterns.
Estimated effort: ~180 SP · Deliverable: AWS dependencies removed and database tier cloud-ready
Phase 3: Days 61-90

Full Cloud Deployment and Productivity Gains

  • Cut over from RabbitMQ to Azure Service Bus through a phased production rollout.
  • Deploy to Azure App Service, Azure Container Apps, or AKS based on the selected landing zone.
  • Enable CI/CD pipelines and automatic scaling policies.
  • Integrate Azure Monitor for end-to-end observability.
Estimated effort: ~102 SP · Deliverable: a production-ready cloud-native asset management platform
